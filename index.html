    How it works

    Risk Radar is a small LLM workflow built to fit a program manager's existing routines (standups, steering reviews, go-live readiness) and flag trouble early.

    Why these design choices

    • Grounded and auditable: every item traces to a source_id, so the PM can defend it in a steering review and the model cannot quietly make up a risk.
    • Third-party aware: the schema forces an SLA, incident-ownership or rollback note for every external integration, which is where cross-organisation programs most often break.
    • Ready for decisions: the output is a prioritised register with owners, a RAG status and the top 3 actions for the week, not a summary.
    • Easy to plug in: the JSON output can feed a Jira sync, a weekly exec email or a delivery-health dashboard.

    Where it would go next

    Native connectors (Slack, Jira and Confluence APIs) → scheduled runs → a diff against the last run to flag new and escalating risks → a drafted weekly stakeholder update, with the register posted to the program's single source of truth.
